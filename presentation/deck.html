The Solution

How it works

Control flow

A pay-per-request handshake where quality is disclosed up front and money is returned automatically when it slips.

05
STEP 1 / 6

Client requests content

  • An ordinary HTTP request — nothing custom yet
  • The agent simply asks for what it needs
request.http
GET /v1/price/BTC
Host: api.example.com

// "What's the current
// price of BTC?"
Control flow
06
STEP 2 / 6

Server responds with HTTP 402

  • Returns the price of the requested content
  • Extended metadata carries the URL of a metrics endpoint
  • Metrics are served as JSON
402 Payment Required
HTTP/1.1 402
{
  "price": 0.05,
  "currency": "USDC",
  "metrics_url":
    "/.well-known/metrics"
}
Control flow
07
STEP 3 / 6

Client requests metrics

  • Server returns a JSON quality report
  • Uptime
  • Service quality metrics
  • Arbitrary, domain-specific eval results
  • Evaluated as natural language
metrics.json
{
  "uptime": "99.98%",
  "accuracy": 0.97,
  "freshness_ms": 120,
  "eval": "answers are
    accurate & current"
}
Control flow
08
STEP 4 / 6

Client judges the offering

  • Is the price acceptable?
  • Is the service reliable?
  • Do the evaluations look good?
  • ✕  If not — bail on the transaction
  • ✓  If good — send the x402 payment
decision.ts
if (price <= budget
  && metrics.ok()) {
  pay(invoice); // ✓
} else {
  abort(); // ✕
}
Control flow
09
STEP 5 / 6

Server delivers the content

  • Payment clears, the response is returned
  • The client is happy
  • …or are they?
200 OK
HTTP/1.1 200 OK
{
  "symbol": "BTC",
  "price": 64218.40,
  "ts": 1717603200
}
Control flow
10
STEP 6 / 6

Server evaluates itself

  • Runs domain-specific evaluations on what it served
  • Stores results to be returned as service quality
  • If a request triggers quality concerns → automatically return the money
async eval worker
const score = eval(resp);
if (score < threshold) {
  refund(tx);
  // funds → sender
}
store(score);
